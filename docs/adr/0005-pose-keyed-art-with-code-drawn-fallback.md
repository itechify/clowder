# Pose-keyed art with code-drawn fallback

The game's art is generated outside the repo (by the author's assistant, from an art brief), so engineering must never wait on it and no image may need a code change to land. Every image is therefore addressed only by a key in an art manifest (`src/art/manifest.ts`), which is data: each key's kind, canvas size, and anchor. Cats and House Cats share one 512×512 transparent canvas and one scale, sitting at bottom centre on a line 64 pixels above the bottom edge, which leaves room for a tail dangling over the Shelf; the room, furniture, and UI are authored at 3× the 390×844 design size. A delivered image is a PNG named for its key in `art/raw/`; the build packs whatever has been delivered into compressed atlases, and at runtime a key without a delivered image draws the existing code-drawn art into a texture under the same key, at the same size and anchor. Scenes ask for art by key and cannot tell the difference. We rejected importing images directly into scene code, which couples every delivery to an engineering change, and rigged or frame-by-frame animation, which the generated art cannot supply consistently; motion is code-driven over single poses instead. The code-drawn fallback is also the permanent answer for any image that cannot be generated consistently.
