# Phaser renders the game; React only renders the shell

Clowder should feel like a game, not a card-shaped web UI, so every in-Run surface (living room, Couch, Hand, Shelf, Shop) is drawn in Phaser, with Cats picked up, seated, and scored as animated objects. React is limited to the shell around it: settings, PWA install and update prompts. We rejected a DOM/React-only build, which would be quicker for a prototype and better for accessibility, because it pulls the feel toward menus and panels. Scoring and all rules live in a pure TypeScript engine with no Phaser dependency, so the renderer stays swappable and the score preview and tests use the same code the game does. Toolchain mirrors the author's existing Phaser project (pnpm, Vite, TypeScript, Biome, Vitest, Playwright, Workbox PWA) for web and mobile.

**Amended (presentation milestone, #42):** the results screen at the end of a Run was first a React panel laid over the sleeping living room, as a "between-Run screen". It moves into Phaser too, drawn into the room itself (a title sign, the Best Play's photo on the wall, the Star Cat asleep in a cat bed, the Nights cleared by the moon, and a New Household button), because a DOM panel is exactly the menu feel this decision exists to avoid. To keep the results' content within reach of screen-reader users, the shell keeps a visually hidden, `aria-live` text summary of the results, rendered exactly while the scene shows them and from the same presentation model; it is the only between-Run DOM the shell renders. New Household is then pressed in the scene only, like every other in-Run control.
